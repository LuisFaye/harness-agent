# 架构说明

本文描述当前实现，不记录阶段计划和历史迁移过程。

## 系统组成

~~~mermaid
flowchart LR
    UI[React 工作台] --> API[FastAPI]
    CLI[CLI / Worker] --> Service[业务服务层]
    API --> Service
    Service --> Runner[Agent / Skill 执行器]
    Runner --> Tools[Tool / Skill / MCP]
    Service --> DB[(MySQL)]
    Service --> FS[用户工作区与产物]
    Runner --> Model[OpenAI 兼容模型]
~~~

- `frontend/`：React + TypeScript 工作台。
- `src/daily_agent/api.py` 与路由模块：认证、会话、运行、文件、能力和设置接口。
- `src/daily_agent/services/`：业务编排，不依赖具体展示层。
- `src/daily_agent/agent.py`：Agno 模型和工具装配。
- `src/daily_agent/skill_*`：Skill 发现、兼容分析、执行和会话状态。
- `src/daily_agent/mcp_*`：MCP 配置、连接、同步和工具调用。
- `sql/mysql_memory.sql`：数据库基线结构。

## 请求执行链路

一次请求先经过认证和用户范围校验，再由服务层选择执行路径：

1. 显式 `/command` 或尚未结束的确定性 Skill 会话，交给对应 Skill runtime。
2. 普通自然语言请求进入 Agent loop，模型只能看到当前启用且可执行的工具。
3. 工具调用前执行参数校验、能力安全检查和必要的用户确认。
4. 工具结果返回模型；长内容先保存为证据，只把预览和引用放进上下文。
5. 最终回答、结构化内容、引用和运行状态分别持久化并流式发送给前端。

`POST /ask/stream` 使用 NDJSON v2。事件带有 `run_id`、递增 `sequence`、时间和类型，前端断流后可通过运行事件接口补拉。取消请求先进入 `cancel_requested`，执行器确认后结束为 `cancelled`。

## 上下文与记忆

上下文由系统指令、用户偏好、相关长期记忆、历史摘要、近期原生 user/assistant 消息和本轮输入组成。历史过长时会生成并保存摘要，同时保留近期原始消息，避免每轮重复塞入完整会话。

网页和文件正文超过内联预算后进入证据库。模型先得到可识别的摘要和证据 ID，需要细节时再调用读取工具。这样能控制 Token 消耗，同时保留来源 URL、文件位置和运行关联。

## 状态模型

运行状态来自真实事件，而不是模型的隐藏推理。主要包括：

- 运行创建、开始、等待确认、取消、完成和失败。
- 工具开始、工具结束和可公开的进度说明。
- 回答开始、增量文本、结构化块和引用更新。
- 文件、产物、证据以及与本次运行的关联。

MySQL 是会话、运行、事件、用户、邀请、记忆和能力配置的持久化来源；文件正文、附件和产物保存在应用数据目录或用户工作区，数据库只保存元数据和关联。

## 用户与权限

首次初始化的账号是所有者。所有者负责成员、邀请码、模型设置、Tool、Skill、MCP 和数据库连接；普通成员只能访问自己的会话、运行、文件和获授权的分享内容。

身份由服务端会话 Cookie 确定，业务接口不信任客户端自行传入的用户 ID。分享是面向指定成员的只读授权，接收方复制后才形成自己的可继续会话。

## 能力边界

Tool 是可直接注册到 Agent 的函数能力；Skill 为能力补充说明、参数契约和可选执行器；MCP 用于连接外部工具、资源和提示词服务。三者的真实可用状态都由能力中心展示，配置存在不等于运行时已经可调用。

系统不会向用户展示模型私有思维链，只展示可核验的操作进度、工具参数摘要、结果状态和证据。受控 Shell/Git 还会拦截敏感路径与高风险命令；其操作系统级隔离目前依赖 macOS `sandbox-exec`，因此 Docker/Linux 镜像中禁用这两类工具。

## 扩展原则

通用执行、状态、权限、文件和证据能力留在核心；领域能力优先通过 Skill 或 MCP 接入。新增能力时应同时定义输入契约、确认策略、用户隔离、密钥来源、超时和可观测事件，而不只增加一个模型可见的工具名。
