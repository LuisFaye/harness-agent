# official-document

把用户要的正式公文排成红头 `.docx`。版式由本技能固定生成，模型只负责填槽位，不要自己写 `python-docx` 脚本，也不要用 Markdown 冒充红头。

## 使用场景

- 用户说「红头文件」「正式公文」「发个通知」「公告」「决定」
- 用户使用 `/official-document` 或 `/hongtou`
- 需要可下载、可预览的 Word，而不是聊天里的纯文本

## 调用前

1. 发文机关未知时先追问，不要编造单位名或文号。
2. 把用户口述整理成公文语气后再调用，不要把口语原文直接塞进正文。
3. `body` 用纯文本：一级标题单独成行，写成 `一、放假时间`；条款写成 `（一）……`。

## 输入

- `title`：标题，必填。
- `body`：正文，必填。
- `red_header`：红头，必填，例如 `××公司文件`。
- `doc_number`：发文字号，可选。
- `recipients`：主送机关，可选。
- `issuer`：落款单位，可选；默认从红头去掉「文件」。
- `issue_date`：成文日期，可选；默认当天。
- `filename`：输出文件名，可选。

## 输出

文件写入工作区 `outputs/`。本轮结束后面板上会出现产物卡片，用户可预览和下载。回复里只说明已经生成，不要让用户去代码目录找文件。
